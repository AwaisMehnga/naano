No. A production webhook URL only delivers events to that public host. Local Laravel never sees them.

Stripe sends events to the URLs you register. It cannot reach `localhost`, and a production endpoint does not proxy back to your machine.

What happens in practice:

- Local top-up / payout → Stripe fires the event → **production** gets it (if that endpoint is in **test** mode) → **local wallet stays unchanged**
- Live-mode production webhook → local test events **do not** go there at all (test and live are separate)

Local still needs one of:

1. `stripe listen --forward-to http://localhost:8000/api/stripe/webhook`
2. A public tunnel (`ngrok`, Cloudflare Tunnel) registered as its own Dashboard endpoint

You can keep the production URL and use the CLI at the same time. They are independent. Use the signing secret that matches the path the event actually took (CLI `whsec_` locally, Dashboard `whsec_` on production).
