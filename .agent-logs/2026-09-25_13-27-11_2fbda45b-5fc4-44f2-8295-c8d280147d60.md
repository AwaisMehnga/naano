Not as the primary path. Audience details are built **inline** during LinkedIn sync, not by a dedicated audience job.

**What runs**
1. On LinkedIn verify / refresh, `LinkedInSyncService::syncPosts()` calls Apify, builds engagers → `AudienceMixBuilder`, then writes a `CreatorAudienceProfile` snapshot (followers, connections, `audience_mix`).
2. That sync is **synchronous** in the request so posts + audience exist without a queue worker.
3. `SyncLinkedInPostsJob` exists only as a **fallback** if that inline sync throws — it retries the same `syncPosts()` work.

**Reading audience** is just the API (`AudienceController` → `CreatorAudienceService`) against the latest snapshot. No recurring/scheduled audience job.
